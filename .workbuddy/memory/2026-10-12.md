## vscode-webai 镜像项目 — 五项 bug 修复

项目根目录名即项目名 → 镜像/容器名统一为 `vscode-webai`（原名 code-server-ai 已全部替换）。

### 1. Oracle Instant Client libaio 依赖（根因 + 修复）
- **根因**：Debian 13 (trixie) 的 time64 迁移把 `libaio1` 改名 `libaio1t64`，且 **SONAME 变成 `libaio.so.1t64`**；
  Oracle 的 `libclntsh.so` 硬依赖 SONAME `libaio.so.1` → 报 `libaio.so.1: cannot open shared object file`，
  python-oracledb thick 报 DPY-3010/3012。已在 Debian 13 容器实测复现。
- **修复**：Dockerfile §1b 装包后补软链接 `libaio.so.1 -> libaio.so.1t64.0.2` + `ldconfig`。
- **踩坑1**：`libaio.so.1t64` 是**软链接**，`find -type f` 匹配不到 → 必须去掉 `-type f`。
- **踩坑2（重要）**：**不能用 `ldconfig -p | grep libaio.so.1` 做断言** —— ldconfig 按 SONAME 去重，
  修复成功后 `ldconfig -p` 里也只会出现 `libaio.so.1t64`。唯一可信的是
  `python3 -c "import ctypes; ctypes.CDLL('libaio.so.1')"`（让动态加载器按名字真解析）。
- Dockerfile §7 加了构建期强校验：`ldd libclntsh.so` 出现任何 `not found` 直接 fail 构建。
- 实测结果：修复后 ldd 无缺失、ctypes 加载 OK、python-oracledb 26.0.1 thick 激活（Client 21.23）。

### 4. opencode 可选预装 + 热升级卷
- 新增 build-arg `INSTALL_OPENCODE`（默认 false）与 action/workflow 的 `install-opencode` 勾选项（默认 false）。
- 路径约定：镜像烧录 `/usr/local/bin/opencode`；热升级卷 `./volumes/opencode-binary` → `/opt/opencode/bin`（PATH 优先）。
- **Dockerfile 必须用 `COPY opencode-bin-cli/ /tmp/...` + RUN 条件安装**：不能用
  `COPY opencode-bin-cli/opencode-* /usr/local/bin/opencode`（通配无匹配直接构建失败）。
- 因此 `opencode-bin-cli/.gitkeep` 必须入库，且源码包要保留该占位文件（否则解包后重建失败）。

## 追加：Oracle 版本锁定 21c + 本机跑起整套 compose

### Oracle Instant Client 版本策略（已锁定 21c）
- x86_64 → **21c (21.23.0.0.0)**，URL 固定 `.../2123000/instantclient-basic-linux.x64-21.23.0.0.0dbru.zip`
- arm64 → Oracle **从未发布 21c 的 arm64 包**，Dockerfile 自动降级 19c (19.32) 并在日志告警
- 版本标记烧录到容器内 **`/opt/oracle/VERSION`**（版本标签 + 下载 URL），
  `test-oracle-instantclient` 会打印，方便核对线上镜像实际版本
- 结论：版本与 libaio 修复解耦，换版本只需 `--build-arg OIC_URL=`

### 本机启动整套服务（Windows + Docker Desktop）
- **本机 8080 被用户的 Dify 栈占用**（`docker-nginx-1`，属于用户另一个项目，**不可停**），
  `dify-metrics-web` 占 9200。以后在本机跑本项目要避开 8080。
- 因此把 compose 端口参数化：`"${CODE_SERVER_PORT:-8080}:8080"`，
  并在项目根目录加了本机用的 `.env`（`CODE_SERVER_PORT=8081`，已加入 .gitignore）。
  服务器部署无 .env → 仍用 8080。
- 启动命令：`docker compose up -d --build` → 容器 `vscode-webai`，`healthy`，
  healthz 200、登录页正常，访问 http://localhost:8081 ，密码 root1234。
- 实测确认：Oracle `libclntsh.so -> libclntsh.so.21.1`；Node v24.21.0 / Python 3.13.16 / Go 1.27.2；
  `~/.bashrc` 命中挂载文件；npm prefix = `/home/coder/.local`。
- **热升级卷实测有效**：往 `./volumes/opencode-binary/opencode` 放一个可执行文件，
  容器内 `/opt/opencode/bin/opencode` 立刻可执行（目录 bind mount 是实时的，无需重启）。
- 已知小现象（既有设计，未改）：`./volumes/local-bin`(空) 挂到 `/home/coder/.local` 会遮住
  镜像里预建的 `.local/bin`，首次 `npm i -g` 时 npm 会自行创建该目录，不影响使用。

- **全局配置目录是 `~/.config/opencode`（无前导点）**，官方文档明确写 "NOT ~/.opencode/"。
  带点的 `.opencode` 只用于**项目级**（`<项目根>/.opencode/skills` 等）。
- 原项目写的是 `~/.config/.opencode` → 错误，配置放了不生效。
- 三处必须同时改（漏一处就会挂到空目录）：Dockerfile §10 预建目录、
  compose 卷目标、文档。已全部改为 `~/.config/opencode`。
- 子目录支持复数与单数（`skills`/`skill`、`agent`/`agents`），推荐复数。
- 登录态在 `~/.local/share/opencode/auth.json`（不在配置目录里），已由 opencode-share 卷持久化。
- 配置**只在启动时加载一次**，改完必须重启 opencode。

### 容器 HOME 说明文档
